# no-ai

AI 写的文字有一批高度重复的固定模式。这个技能先教怎么识别，再教怎么改掉。

## 判断原则

- 单个模式偶尔出现不算 AI 味，人也会这么写。
- 密集出现 + 内容空洞 + 到处对称工整，才是典型 AI 味。
- 越是"信息量低但语气笃定、结构特别齐整"，越可疑。
- 来源是模型被训得追求礼貌、完整、面面俱到、正能量收尾，于是套话和排比过量。

## 常见口癖清单

### 一、标志性词汇

英文高频词（尤其 delve 几乎是招牌）：
delve, dive into / deep dive, leverage, harness, robust, seamless, streamline, empower, foster, elevate, unlock, navigate, unleash, boasts, nestled, realm, landscape, tapestry, testament, underscore, pivotal, crucial, vital, game-changer, cutting-edge, state-of-the-art, holistic, myriad, plethora。

中文营销/黑话词：
口径、赋能、抓手、闭环、生态、链路、飞轮、范式、颗粒度、心智、维度、沉浸式、一键、打造、助力、护航、深耕、精准、高效便捷、全方位、多维度、可审计。

### 二、开场套话

- EN：In today's fast-paced world… / In the ever-evolving landscape of… / In an era where…
- ZH：在当今……的时代 / 随着科技的飞速发展 / 在这个日新月异的时代 / 众所周知

正文还没开始，先来一句放之四海而皆准的宏大铺垫。

### 三、否定式重构 / 对偶

- EN：It's not just X, it's Y. / This isn't merely X—it's Y. / It's not about X; it's about Y.
- ZH：不仅仅是……更是…… / 不是……而是……

用一个假对立把一句普通陈述包装得很有张力。

### 四、过渡词与信号词堆叠

- EN：Furthermore, Moreover, Additionally, That said, Ultimately, It's worth noting that, It's important to note that, Here's the thing。
- ZH：值得注意的是 / 需要指出的是 / 总而言之 / 综上所述 / 总的来说 / 其实 / 事实上 / 某种程度上。

靠连接词硬撑逻辑感，很多可以整句删掉。

### 五、三词排比（rule of three）

- EN：clear, concise, and compelling / fast, reliable, and scalable。
- ZH：高效、便捷、智能 / 稳定、安全、可靠。

三个近义词并列，凑气势而非增加信息。

### 六、结构套路

- 强行 First / Second / Finally，或事事都用 1、2、3、4 罗列，哪怕本该是一段话。
- 每段或每小节末尾都补一句重述总结。
- 加粗关键词后跟冒号解释：`**关键点：** ……`。
- 冒号式标题：`概述：xxxx` / `Overview: xxx` / `深度解析：xxx`。
- Emoji 当小标题或句尾装饰：✨🚀🔥✅。
- 结尾一段升华 / 口号式总结。

### 七、标点与装饰符号

- 破折号滥用——像这样——到处往句子里插。
- 大量括号（用来补充）（还层层嵌套）打断阅读。
- 用「」、『』、【】等特殊括号给普通概念加框，或用 ☆、◆、▷、→ 等符号装饰正文、标题和结论。这类非必要标记按 AI 表达痕迹处理，直接删除，例如将「未知」改为未知。
- 公式、代码、参考文献标注和有明确专业含义的符号按原义保留；实际引文中的标点遵循原文与写作规范。

### 八、修辞与语气

- 反问句开场：Ever wondered…? / 你是否曾经……？
- 谄媚开场：Great question! / Certainly! / 太棒了！ / 这是一个非常好的问题。
- 收尾讨好：I hope this helps! / Feel free to ask! / 希望这对你有帮助！ / 如有疑问随时问我。
- 空泛权威：Studies show… / Experts agree… / 研究表明 / 专家指出（没有具体出处）。
- 过度对称的排比长句，一段里句式完全平行。
- whether you're X or Y… / when it comes to X…

### 九、术语
- 不要出现太多的工程化术语 phase_a run_xxx 代码模块名称
- 在学术论文写作的时候, 符合学术化的术语规范
- 同一专业对象保持同一名称，不为避免重复而轮换“模型、框架、系统”等称呼。

### 十、过度防御性表达与流程套话

- 连续退缩：不能断言、不能确定、尚不能确认、不一定、不完全、未必、不保证。
- 反复切割结论：不能仅凭、只能说明、不足以证明、不意味着、不等于、不代表、不构成、不能据此。
- 预设误解再纠正：不是说……、并不是……、不是……而是……、更准确地说……，但上下文没有人提出那个误解。
- 用流程展示谨慎：动辄核验、探针、审计、冻结、快照、哈希、门禁、回滚、验收矩阵、证据链、归档，把简单任务写成完整治理流程。
- 先说“你说得对”，紧接着堆满保留意见、免责声明或检查步骤，正文迟迟不回答问题。
- 回答完当前问题，又主动追加泛化效果、其他部署场景、额外验证或后续工作，即使措辞简短，仍是在扩大用户没要求的讨论。

结合用户当前要求判断，具体改法见下文“避免防御性写作”。

## 去 AI 味工作流

1. 通读原文，对照上面清单标出 AI tell 的地方。
2. 逐条替换或删除，只改表达不改原意。
3. 检查保留意见、否定句和流程说明：删掉只为防止被质疑而写的内容，以及用户没要求的其他情况和额外任务。
4. 再通读一遍，确认没有为了去 AI 味把话改得生硬、跳跃或残缺，也没有夸大结论或虚构已完成的工作。

## 改法

- 套话开场直接删，第一句就进入正题。
- "不是 X 而是 Y" / "不仅仅是……更是……" → 直接陈述结论。
- 破折号 → 换成句号、逗号，或直接删。
- 括号补充 → 并进正文，或删掉次要的。
- 三词排比 → 只留最准确的一两个。
- buzzword（赋能、抓手、leverage、seamless 等）→ 换成具体的动词或名词。
- 检查整句和整段是否必要：删去后不影响当前问题的理解，就删。同一结论再次出现时，应带来新证据或解释；只换说法的复述也删。
- 修改时优先替换、合并已有句子。每次补充内容，都检查是否与原文重复，避免解释和限定越积越多。
- `**关键词：** 解释` → 改回正常句子。
- 冒号式标题 `概述：xxx` → 改成正常短语。
- 删谄媚开场（"这是个好问题"）和讨好结尾（"希望对你有帮助"）。
- 强行的 1234 罗列 → 改成连贯段落。

## 不要矫枉过正

- 破折号、括号、列表本身没问题，只有滥用或内容空洞时才改。真正的操作步骤、并列清单、代码，该用列表就用列表。
- 别为了"像人"故意写错字、断句破碎、逻辑跳跃。
- 保留专业术语和数字精度，技术含义不能改。
- 保持原文的语言和大致语气：中文改后还是中文，正式的保持正式。
- 目标是自然清楚，不是刻意口语或刻意简陋。

## 避免防御性写作

围绕用户当前要求作答，答完就停。不要为了显得严谨，主动追加用户没问的其他场景、局限、验证任务或后续工作。只为预防质疑而写的句子直接删掉，不必改成更短的保留意见。

### 改写规则

- 直接说与当前问题有关的事实、结论或动作。
- 将“不能说明什么”改为“实际说明什么”，不要惯性接上“但仍需验证”“其他情况另行考虑”。
- 用户问当前结果，就写当前结果；不要顺带讨论泛化、长期效果或其他部署场景。
- 用户要求修改，就说明修改内容；不要自动附送核验、审计、归档等流程。实际需要做的工作按任务处理，无须把每个步骤都写进回复。
- 不凭空预设误解，再用“不是……而是……”纠正。

### 改写示例

| 用户要求 | 原句 | 改写 |
| --- | --- | --- |
| 汇报当前数据上的实验结果 | 这不能证明方案有效，也不意味着它一定能泛化，只能说明它在当前数据上有提升。 | 方案在当前数据上有提升。 |
| 给出下一步排查动作 | 不能仅凭这段日志断言根因，也不能保证就是缓存问题，还需要查看报错前后的缓存读写记录。 | 查看报错前后的缓存读写记录。 |
| 说明方案是否适用于单机部署 | 这不是在否定原方案，而是在更准确地界定它的适用边界：原方案适用于单机部署，跨节点共享状态需要另行设计。 | 原方案适用于单机部署。 |
| 修改这处本地配置 | 我会修改这处本地配置、检查服务能否正常启动，并建立基线、记录指纹、跑验收矩阵和归档。 | 我会修改这处本地配置。 |

保留原有事实、数值和确定程度；删掉题外补充，不补造结论或完成状态。
