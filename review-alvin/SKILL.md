# review-alvin

## 确定 review 对象

- 工作区有未提交改动：review 当前 diff（`git status`、`git diff`、`git diff --staged`）。
- 工作区干净：review 最近一个 commit（`git show HEAD`）。
- 存在远端 base 分支：补充看当前分支相对 base 的整体 diff（`git diff <base>...HEAD`），覆盖该分支全部提交而不只是最新一条。

## 自主验证

目标是尽量真的把系统跑一下，而不是只读代码。

1. 读项目入口和命令来源：`README.md`、`AGENTS.md`、`package.json`、`pyproject.toml`、`Makefile` 等，找到 lint、测试、启动命令。
2. 按从轻到重的顺序运行：静态检查/lint，单元测试，相关的 smoke test，必要时跑最小启动命令确认能起来。
3. 优先跑与本次改动相关的范围，避免无谓的全量耗时。
4. 跑不了就说明原因（缺依赖、需要外部服务、环境受限等），并给出别人能跑的替代命令。

## 审查范围

- 正确性与逻辑，边界条件和异常路径。
- 数据、状态、接口的向后兼容性。
- 依赖与环境变化带来的影响。
- 测试是否覆盖了本次改动。
- 启动和运行时风险（崩溃、死锁、资源泄漏、配置缺失）。
- 安全相关（密钥泄漏、注入、越权、不安全默认值）。

对不确定的问题标注假设，把风格偏好和必须修复的问题分开。

## 输出结构

```text
发现的问题（按严重程度排序）：
- 严重：文件路径，问题是什么，为什么有风险，如何复现或验证，建议怎么改。
- 一般：...
- 建议：...

验证情况：
说明实际运行过的命令和结果（通过/失败/未运行及原因）。

剩余风险：
说明没覆盖到的场景，或需要人工确认的前提。
```
