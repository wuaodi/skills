# 中文 Git 提交

## 提交约定

先检查工作区、暂存区和实际 diff，只暂存本次请求涉及的文件，保留用户已有的其他改动。按用户请求执行提交或提交并推送。

标题为 `YYYYMMDD 类型：一句话说明`，日期取提交当天，类型按改动选新增、修复、更新、重构、文档或测试。正文简述目的、更改、验证；只有还需他人验证时才补充环境和命令，小改动每项一句即可。

用 UTF-8 临时消息文件配合 `git commit -F <文件>` 保留真实换行，遵循当前 shell 的语法。只记录实际运行过的验证。

获准推送时，已有上游用 `git push`，首次推送确认远端后用 `git push -u origin HEAD`。遵守环境中的 HTTPS/GCM 认证约定；不强推、不跳过 hook、不改 Git 配置。失败后报告原因，不用破坏性命令重试。

## 大文件与归档

- 排除密钥、可再生成的构建产物、缓存、批量日志和实验输出；必要的发布资源按项目要求保留。
- 单文件超过 10 MB，先确认入库必要性；超过 50 MB 按本人的仓库约定外置归档，不用 Git LFS。
- 大数据仅在首次出现或实质更新时打包，先查已有归档记录。ZIP 保留相对仓库根目录的路径，优先使用 store 模式。
- 由用户上传至百度网盘 `Alvin/git大文件/<远程仓库名>_archive/`。复用一份归档说明，记录网盘路径、ZIP 名、内容、日期和在仓库根目录解压的恢复方式；未上传时标记待上传。
- 向 `.gitignore` 追加相关规则，保留已有规则。已经跟踪的文件需取消跟踪时，先确认该操作在授权范围内；缺少授权再询问。
