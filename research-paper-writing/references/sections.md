# 章节写作

## Abstract 与 Introduction

摘要通常沿“任务、技术困难、关键思路、实现该思路的贡献、实验结果”展开。篇幅紧时合并思路与贡献；有多个独立贡献时，把每个贡献及其作用放在一起。技术名词应可理解，避免用名称替代机制解释。

Introduction 从结果反推论证：论文解决了什么失败情形，其技术原因是什么，方法为何有效，哪些证据支持。写作时再按读者理解顺序展开。

- 陌生任务先说输入、输出和边界；熟悉任务尽早进入尚未解决的问题。
- 讨论前人工作时给出具体机制、适用条件及局限，不为引出自己而夸大缺陷。新任务没有直接前作时，解释输入约束带来的困难。
- 从已有框架改进时如实交代基础方法，明确新增部分。重要观察应连到实际设计，避免只用新术语描述抽象收益。
- 贡献总结只包含正文真正建立的结果，并与实验或推导对应。

例如，原笔记中 Neural Body 的论证主线是：稀疏视角约束不足，利用跨帧观测，再以锚定在可变形人体模型上的共享潜码实现整合。可借鉴“困难、思路、实现”关系，不套用其领域结论。

## Method

先明确输入、输出与假设，沿实际数据流安排模块顺序。总览图、章节和符号应对应。

一个模块需要讲清楚动机、设计和技术作用，但不必机械拆成三个小标题。先写具体表示或数据结构，再按前向计算顺序说明输入如何变成输出；动机对应真实问题，优势说明成立条件。

例如，Instant-NGP 的批注先定义多层特征表及分辨率，再描述坐标映射、特征查询、插值与拼接。Neural Body 的 code diffusion 则先说明稀疏潜码难以直接连续查询，再引出扩散与插值。

给足复现关键机制所需的定义、维度、损失和训练/推理差异；一般超参数按投稿格式放到实现细节或补充材料。不要隐去决定方法是否成立的条件。

## Related Work 与 Experiments

Related Work 按相关技术路线分组，比较机制、假设及适用范围，覆盖最接近和最强的工作。把本文差异说到技术层面，避免逐篇罗列。

实验围绕论文主张安排：

- 公平比较支撑效果结论，核对数据划分、预处理、训练资源和评估协议。
- 消融支撑关键设计的作用，存在耦合时检查组合效果，避免把相关性写成因果解释。
- 泛化、效率或鲁棒性只在有相应测量时声称。说明硬件、统计口径和测试范围。
- 数字与图表一致，区分绝对变化、相对提升和百分点；报告对结论有影响的失败情形与波动。

不要把上述维度扩展为每篇论文都必须新增的实验清单，依据实际主张指出缺失证据。

## Conclusion

简述解决的问题、核心方法和已证明的结论，不引入新结果。局限具体到假设、数据、计算或适用场景；已知技术缺陷同样如实交代。未来工作只保留与局限直接相关的方向。
