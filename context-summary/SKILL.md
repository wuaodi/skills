# 项目交接

维护项目根目录唯一的 `CONTEXT.md`，帮助后续会话快速继续工作。有现成文件先读，再按代码和实际执行结果核实；已有其他交接约定时沿用，避免重复。

只记录下次工作需要的信息，通常 40–80 行，简单项目更短：

- 项目用途、当前目标，以及已完成和待完成事项。
- 关键目录、入口和配置文件的职责；只列会影响后续工作的路径。
- 已确认的启动、测试或构建命令及必要环境条件。
- 关键决策的原因、已知阻碍和下一步。

更新时替换过期信息，保留仍有效的决策。未验证的命令和推测明确标注；不要写密钥、聊天流水账、完整文件树，也不要重复 AGENTS.md 或 README 已讲清的内容，可直接指向相关文件。

先检查根目录和代表性入口，再按缺口补读；无需遍历全仓库。最终简述更新位置和仍未确认的事项。
